### Задание 5. **(2)**

*Объясните работу фрагмента программы на С++. В частности, почему* $x+x-x=x$, *но при этом*
$(x\cdot 2)/2\neq x$? *В отчете надо привести вычисления, приводящие к ответу.*
```
unsigned short x = 40000;
unsigned short y = x + x;
unsigned short z = x * 2;
y = y - x;
z = z / 2;
std::cout << y << " " << z << std::endl;
```

```
Программа:

    unsigned short x = 40000;
    unsigned short y = x + x;
    unsigned short z = x * 2;
    y = y - x;
    z = z / 2;
    cout << y << " " << z;

unsigned short — это 16 бит, диапазон 0..65535.
Всё, что больше 65535, при записи в unsigned short
обрезается по модулю 65536 (остаётся только младшие 16 бит).

Что происходит по шагам:

1) x = 40000.

2) y = x + x = 80000.
   80000 не влезает в unsigned short.
   80000 mod 65536 = 80000 - 65536 = 14464.
   y = 14464.

3) z = x * 2 = 80000.
   То же самое: z = 14464.

4) y = y - x = 14464 - 40000 = -25536.
   Отрицательное число тоже обрезается по модулю 65536:
   -25536 + 65536 = 40000.
   y = 40000.

5) z = z / 2 = 14464 / 2 = 7232.
   Здесь деление нормальное, обрезать нечего.

Итог: cout выведет "40000 7232".

Теперь главный вопрос:
почему x + x - x = x, а (x * 2) / 2 ≠ x?

Смотрим по модулю 65536.

Случай с y:
   x + x даёт 2x = 80000, но сохраняется только 14464,
   то есть мы как бы "потеряли" 65536.
   Дальше вычитаем x:
   14464 - 40000 = -25536.
   И снова берём по модулю 65536:
   -25536 + 65536 = 40000.
   Получилось ровно x.

   Почему так вышло? Потому что вычитание — обратная
   операция к сложению, и по модулю это работает:
   (2x mod M) - x mod M = (2x - x) mod M = x mod M = x.
   То есть потерянный при сложении "лишний" модуль
   ровно там же и прибавился обратно при вычитании.
   Они взаимно уничтожились.

Случай с z:
   x * 2 даёт 2x = 80000, сохраняется 14464.
   Но теперь мы не вычитаем x обратно, а делим на 2:
   14464 / 2 = 7232.
   А надо было бы получить 40000.
   Куда делось остальное?

   Дело в том, что при обрезании мы потеряли 65536,
   а деление на 2 теряет уже только половину от потерянного:
   (2x mod M) / 2 = (2x - M) / 2 = x - M/2 = 40000 - 32768 = 7232.
   То есть 32768 "пропало" безвозвратно — деление не может
   вернуть то, что было отброшено по модулю.

Коротко:
   + и - по модулю — взаимно обратны, поэтому "переполнение"
   отменяется обратной операцией.
   * и / по модулю — не взаимно обратны, потому что деление
   в C++ — это обычное целочисленное деление, а не "модульное".
   Поэтому восстановить исходное x не получается.
```

### Задание 8 **(2)**

*Найдите результаты вычисления следующих выражений без использования компьютера
или калькулятора. Процесс вычислений должен быть отображен в отчете.*
* `(1000 & 100) << 10`
* `(1000 >> 4) & 15`
* `~1234 + 1234`
* `(1000 ^ 500) & 63`
* `(100 << 3) + (100 >> 3)`
```
1) (1000 & 100) << 10

Переведём числа в двоичный вид:

1000 = 512 + 256 + 128 + 64 + 32 + 8 = 1111101000₂
100  = 64 + 32 + 4 = 0001100100₂

Выполняем побитовое И:

  1111101000
& 0001100100
------------
  0001100000₂

0001100000₂ = 64 + 32 = 96

Теперь сдвиг влево на 10 — это умножение на 2¹⁰ = 1024:

96 << 10 = 96 * 1024 = 98304

Ответ: 98304

--------------------------------------------------

2) (1000 >> 4) & 15

Сначала сдвиг вправо на 4 — это целочисленное деление на 2⁴ = 16:

1000 >> 4 = 1000 / 16 = 62 (остаток 8)

Теперь 62 & 15. Число 15 — это 1111₂, то есть берём младшие 4 бита.

62 = 32 + 16 + 8 + 4 + 2 = 111110₂
15 = 1111₂

  111110
& 001111
--------
  001110₂ = 14

Ответ: 14

--------------------------------------------------

3) ~1234 + 1234

Операция ~ — побитовое отрицание. Для знаковых чисел в дополнительном коде:

~x = -x - 1

Поэтому:

~1234 = -1234 - 1 = -1235

Тогда:

~1234 + 1234 = -1235 + 1234 = -1

Ответ: -1

--------------------------------------------------

4) (1000 ^ 500) & 63

Переведём 1000 и 500 в двоичный вид:

1000 = 1111101000₂
500  = 0111110100₂   (256 + 128 + 64 + 32 + 16 + 4 = 500)

Выполняем XOR:

  1111101000
^ 0111110100
------------
  1000011100₂

1000011100₂ = 512 + 16 + 8 + 4 = 540

Теперь 540 & 63. Число 63 = 111111₂, то есть берём младшие 6 бит.

540 = 512 + 28
512 кратно 64 (64 * 8 = 512), поэтому остаток:

540 mod 64 = 28

Значит:

540 & 63 = 28

Ответ: 28

--------------------------------------------------

5) (100 << 3) + (100 >> 3)

100 << 3 = 100 * 2³ = 100 * 8 = 800
100 >> 3 = 100 / 2³ = 100 / 8 = 12 (целочисленное деление)

Складываем:

800 + 12 = 812

Ответ: 812

--------------------------------------------------

Итоговые результаты:

(1000 & 100) << 10   = 98304
(1000 >> 4) & 15     = 14
~1234 + 1234         = -1
(1000 ^ 500) & 63    = 28
(100 << 3) + (100 >> 3) = 812
```

Ищем все целые x, такие что x | (x+1) = 895.

1) Переведём 895 в двоичную систему:

   895 = 512 + 256 + 64 + 32 + 16 + 8 + 4 + 2 + 1

   бит 8 = 1
   бит 9 = 1

   бит:  9 8 7 6 5 4 3 2 1 0

   1100111111₂ =

### Задание 2 **(3)**

*Какие значения можно присвоить целочисленной переменной* **x**,
*чтобы результатом выражения `x&(x-1)` стало число 0?
Найдите все значения без использования компьютерных вычислений 
(среди них есть отрицательные числа). Обоснуйте ответ.*

```
Выражение x & (x - 1) обнуляет младший единичный бит числа x.

Например:
    x = 12 = 1100₂
    x-1 = 11 = 1011₂
    x & (x-1) = 1000₂ = 8
    Младшая единица (бит 2) обнулилась.

Значит, x & (x-1) = 0 тогда и только тогда,
когда в числе x установлен не более чем один единичный бит.
То есть x — это либо 0, либо степень двойки.

Рассмотрим 32-битный знаковый int (дополнительный код).

Положительные значения и ноль:
    0
    1 = 2^0
    2 = 2^1
    4 = 2^2
    8 = 2^3
    ...
    1073741824 = 2^30

Число 2^31 = 2147483648 уже не влезает в положительную часть int,
потому что INT_MAX = 2147483647.

Отрицательные значения:
В дополнительном коде отрицательное число имеет старший бит 1.
Чтобы у числа был только один единичный бит, этот бит должен быть
старшим, а все остальные — нулями.
Это число -2^31 = -2147483648 (в hex: 0x80000000).

Проверка для x = -2147483648:
    x     = 0x80000000
    x - 1 = 0x7FFFFFFF
    x & (x-1) = 0x80000000 & 0x7FFFFFFF = 0

Других отрицательных решений нет: если установлен ещё хотя бы один
бит, кроме старшего, то младший единичный бит обнулится, но старший
останется, и результат не будет равен 0.

Итоговый список всех значений x для 32-битного int:

    0,
    1, 2, 4, 8, 16, 32, 64, 128,
    256, 512, 1024, 2048, 4096, 8192,
    16384, 32768, 65536, 131072, 262144,
    524288, 1048576, 2097152, 4194304,
    8388608, 16777216, 33554432, 67108864,
    134217728, 268435456, 536870912,
    1073741824,
    -2147483648

Если ширина int другая (например, 16 бит), то решения аналогичны:
0, все положительные степени двойки, влезающие в тип,
и минимальное отрицательное число -2^(N-1).
```

### Задание 3 **(3)**
